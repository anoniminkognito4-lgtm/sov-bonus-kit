# Комплект для разработки прототипа расчёта бонусов СОВ

Реализованы этапы M0–M6 локального прототипа: движок, реестр с загрузчиками,
панель Группы СОВ, «что если», личный кабинет и особые случаи.
Остаётся обязательная приёмка на настоящей Windows перед эксплуатацией:
сейчас автоматические проверки выполнены на macOS.
Отчёт по особым случаям: [docs/M6.md](docs/M6.md).
Личный кабинет и права: [docs/M5.md](docs/M5.md).
Проверка моделирования: [docs/M4.md](docs/M4.md).
Проверка условного квартала: [docs/M3.md](docs/M3.md).
Отчёт о реестре: [docs/M2.md](docs/M2.md).
Отчёт о движке: [docs/M1.md](docs/M1.md). История каркаса:
[docs/M0.md](docs/M0.md).

Целевая платформа эксплуатации — **Windows**; разработка сейчас ведётся на
macOS. Подготовлены установка `setup.bat`, запуск `run.bat` и приёмка `check.bat`.
Порядок установки и проверки: [docs/WINDOWS.md](docs/WINDOWS.md).
Для Mac: `sh setup.sh` один раз, затем `sh run.sh`. Для обычной работы после
установки не нужны сеть, Office, LibreOffice и подписка на программного агента.

Переносимый комплект: `build/sov-bonus-kit-portable.zip`. Он не содержит БД,
окружения Mac и кешей. Все проверки одной командой после установки:
`uv run python tools/acceptance.py`; отчёт появится в `build/acceptance`.

Этот архив — рабочая папка для Claude Code. В ней всё, что агенту нужно, чтобы построить прототип по ТЗ: правила расчёта, обезличенный шаблон калькулятора, 28 условных кейсов с эталонными результатами, образцы файлов-источников и пошаговый план. Агент читает `CLAUDE.md` сам при запуске в этой папке.

Реальных данных здесь нет: все сотрудники «Тестов …», проекты «Тестовый проект», суммы придуманы. Шаблон очищен от ФИО, NPV и БГБ. Методология СОВ лежит в `docs/methodology` — это внутренний документ компании, архив не выкладывай наружу.

## Установка средств разработки на Mac (необязательно для запуска панели)

Следующие шаги относятся к первоначальному комплекту разработки через Claude Code.
Для готовой панели достаточно uv и скриптов запуска выше.

1. Откройте «Терминал» (Программы → Утилиты).
2. Установите Claude Code:
   ```bash
   curl -fsSL https://claude.ai/install.sh | bash
   ```
   Откройте новое окно терминала и проверьте: `claude --version`.
   Есть Homebrew — можно так: `brew install --cask claude-code`.
3. Установите `uv` — он поставит нужный Python и библиотеки, системный Python не трогается:
   ```bash
   curl -LsSf https://astral.sh/uv/install.sh | sh
   ```
4. По желанию — LibreOffice. Он нужен только чтобы пересчитывать эталоны при добавлении новых кейсов; для разработки и тестов не нужен.
   ```bash
   brew install --cask libreoffice
   ```
   или скачайте с libreoffice.org.
5. Распакуйте архив, например в `~/Projects/sov-bonus-kit`.

## Запуск агента

```bash
cd ~/Projects/sov-bonus-kit
claude
```

При первом запуске Claude Code попросит войти в аккаунт через браузер и спросит, доверяете ли вы этой папке — ответьте «да».

Без терминала тоже можно: в приложении Claude для Mac есть Claude Code, в нём нужно выбрать эту папку как рабочую. Всё остальное так же.

Первое сообщение агенту:

> Прочитай CLAUDE.md и документы из списка «Что прочитать». Перескажи коротко, что будешь строить и как поймёшь, что этап готов. Потом начни этап M0.

Дальше агент идёт по этапам M0 → M6 и после каждого останавливается с отчётом. Вам на каждом шаге нужно:

- прочитать отчёт и, если хотите, открыть то, что он показывает;
- ответить «дальше» или сказать, что поправить;
- отвечать на вопросы по методологии — агент будет спрашивать, а не додумывать.

Когда агент запрашивает разрешение на команду, читайте, что он хочет сделать. Обычные команды этого проекта: `uv`, `pytest`, `python3 tools/…`, `git`, `streamlit`.

## Как проверить работу агента самому

- **Движок (после M1).** `uv run python tools/compare_golden.py build/results` — по каждому кейсу «OK» или список расхождений в рублях.
- **Пример по шагам.** Откройте `reference/examples/T13_spec.xlsx` и `docs/WORKED_EXAMPLE.md`: там тот же расчёт в ячейках калькулятора и словами. Попросите агента показать тот же кейс в его панели — цифры должны совпасть до копейки.
- **Интерфейс (после M3).** Агент даст команду запуска, приложение откроется в браузере. Пройдите условный квартал: загрузка образцов → проблемы → расчёт → закрытие → файл к начислению.
- **«Что если» (после M4).** В «Сотрудники» выберите T0008 / TP-T05 → «Что если» → «Исторический сценарий» → «Моделировать: Мотивационная веха 3». Сдвигайте факт: бонус растёт до потолка 150% и дальше не меняется. «Сбросить сценарий» возвращает исходный расчёт.
- **Кабинет (M5).** Выберите роль «Сотрудник» и профиль T0002: доступны только его назначения и выписка. Роль руководителя ограничена проектами и сотрудниками из `config/demo_access.json`; это демонстрационные права, не корпоративный вход.
- **Особые случаи (M6).** В «Ручные решения» доступны выплата после ИС, завершение работы при продаже, корректировка закрытого квартала и групповое перераспределение. Источники и ограничения описаны в [docs/M6.md](docs/M6.md).

## Правила, о которых агент знает

- Только условные данные. Реальные калькуляторы ему не давайте: если дадите, он откажется их открывать — так записано в `CLAUDE.md` и закрыто настройкой `.claude/settings.json` (файлы `.xlsm` не читаются).
- Эталоны и шаблон он руками не меняет. Новый кейс добавляется через генератор и пересчитывается в LibreOffice, с вашего согласия.
- Все спорные толкования собраны в `docs/CALC_RULES.md`, раздел 14 (И-1…И-8). Их стоит подтвердить в Группе СОВ; пока они работают как описано.

## Если что-то пошло не так

- `claude: command not found` — откройте новое окно терминала; если не помогло, выполните `claude doctor`.
- Агент «забыл» правила после долгой работы — попросите: «Перечитай CLAUDE.md».
- Хотите начать этап заново — попросите агента откатиться к коммиту предыдущего этапа (`git log` покажет историю).
