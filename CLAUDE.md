# Прототип расчёта бонусов проектных команд (СОВ)

Ты строишь локальный прототип системы, которая заменяет Excel-калькуляторы бонусов проектных команд: реестр данных, загрузчики, движок расчёта по правилам СОВ, панель Группы СОВ, личный кабинет и режим «что если». Работаешь на Mac пользователя. Пользователь — методолог СОВ, а не разработчик: объясняй по-русски, коротко и так, чтобы он мог проверить результат сам.

## Жёсткие правила

1. **Только условные данные.** Все люди, проекты, суммы — из `tests/cases`, `samples` и придуманные по их образцу («Тестов …», `TP-…`, `T0001`). Никогда не открывай, не запрашивай и не загружай реальные калькуляторы (`*.xlsm`), реальные ФИО, БГБ, NPV. Если пользователь даст реальный файл — не открывай его и напомни, что тестируем только на шаблоне: это его собственное правило.
2. **`reference/` и `tests/golden/` руками не правятся** (закрыто в `.claude/settings.json`). Эталоны меняются только через `tools/template_harness/fill_and_recalc.py` и только после согласия пользователя.
3. **Правила расчёта — из `docs/CALC_RULES.md`.** Не придумывай правил. Если правило неясно или код не сходится с эталоном — найди место, объясни расхождение пользователю и спроси. Места с пометкой [И-n] — толкования: делай их параметрами или отдельными функциями.
4. **Движок — чистые функции:** без БД, файлов, сети и текущей даты (дата расчёта — параметр). Один и тот же движок считает основной расчёт и «что если».
5. **Деньги не округляются в промежуточных шагах**; до копеек — только в выгрузке к начислению.
6. **Приложение работает без сети** и без LibreOffice. LibreOffice нужен только стенду эталонов.
7. Ничего не удаляй из комплекта и не переписывай историю git без просьбы пользователя.

## Что прочитать перед работой

1. `docs/SPEC.md` — ТЗ целиком (разделы 4–9 и 11 — главное).
2. `docs/CALC_RULES.md` — точные алгоритмы. Это твоя спецификация движка.
3. `docs/DATA_FORMATS.md` — вход (кейс), выход (`sov-result/1`), файлы-источники, таблицы реестра, выгрузки.
4. `docs/TEST_PLAN.md`, `docs/WORKED_EXAMPLE.md` — как проверяем; один кейс, разобранный по шагам.
5. `docs/TEMPLATE_MAP.md`, `docs/TEMPLATE_VS_SPEC.md` — как устроен шаблон калькулятора и чем текущая практика отличается от ТЗ.
6. `docs/UI.md` — экраны и «что если».
7. `docs/methodology/` — первоисточники (СОВ v2, нормирование РП). Читай по ссылкам «сл. N», целиком не нужно.

## Стек и структура

Python 3.12 через `uv`; SQLite + SQLAlchemy 2; Streamlit; openpyxl для выгрузок; pytest; ruff. Другие зависимости — только если без них никак, и с объяснением.

```
pyproject.toml
src/sov/
  engine/        чистый расчёт: params.py (параметры СОВ по редакциям), rules/*.py, calculate.py, cli.py
  registry/      модели SQLAlchemy, сессия, снимки кварталов, журнал
  loaders/       распознавание, проверка, сопоставление, предпросмотр, применение, откат
  adapters/      реестр -> вход движка (история ставок, NPV по кварталам, продление ПБ у ушедших)
  exports/       файл к начислению, выписка, сводная
  services/      сценарии панели и права ролей
app/             Streamlit: main.py, pages/
tests/           unit/, golden/, autocontrol/ (данные уже есть) + твои test_*.py
tools/           стенд эталонов и генераторы (уже есть)
docs/DECISIONS.md   журнал решений — дописывай
```

Контракт движка: `calculate_case(case: dict, params: SovParams | None = None) -> dict` — кейс из `docs/DATA_FORMATS.md` §1 на входе, `sov-result/1` (§2) на выходе, плюс `problems: [...]`. Сверка: `tools/compare_golden.py` (можно импортировать `compare` в pytest).

## Этапы

После каждого этапа: все тесты зелёные, коммит, короткий отчёт пользователю (что сделано, как проверить, что осталось неясным) — и жди его «дальше».

**M0. Каркас.** `git init`, `uv init`, зависимости, структура выше, `ruff`, pytest с параметризованными тестами по `tests/unit/*.json`, `tests/golden/spec/*.json`, `tests/autocontrol/cases.json` (пока падают). Готово, когда `uv run pytest` запускается и показывает, сколько кейсов ждёт реализации.

**M1. Движок.** Все правила `docs/CALC_RULES.md` §2–12 для кейсов. CLI `uv run python -m sov.engine.cli tests/cases build/results`. Готово, когда зелёные все юнит-тесты, все 27 эталонов (`python3 tools/compare_golden.py build/results` — 0 расхождений) и автоконтроли A01–A13. Порядок кейсов — `docs/TEST_PLAN.md` §5.

**M2. Реестр и загрузчики.** Таблицы `docs/DATA_FORMATS.md` §4, загрузчики всех файлов `samples/` по порядку ТЗ, раздел 5 (тип по заголовкам, проверка, сопоставление по ключам, предпросмотр, применение, повторная загрузка без изменений, откат, журнал). Адаптер реестр → вход движка. Готово, когда `samples` загружаются, расчёт по реестру, собранный по `samples/case_map.csv`, совпадает с эталонами (T16 и T20 — без процентов: в образце одна ставка), повторная загрузка ничего не меняет, откат возвращает реестр.

**M3. Панель Группы СОВ.** Экраны `docs/UI.md` §2, роли-заглушки, выгрузки §5. Готово, когда пользователь может пройти условный квартал: загрузить образцы → увидеть проблемы → исправить загрузкой → рассчитать → закрыть квартал → выгрузить файл к начислению. Smoke-тесты через `streamlit.testing.v1.AppTest`.

**M4. «Что если».** В карточке сотрудника панели, `docs/UI.md` §4. Готово, когда автоматизированы свойства `docs/TEST_PLAN.md` §4 и пересчёт ≤ 1 с.

**M5. Личный кабинет.** `docs/UI.md` §3 и «что если» в нём. Готово, когда тесты прав: сотрудник видит только себя, руководитель — свои проекты без БГБ.

**M6. Особые случаи.** `docs/CALC_RULES.md` §13 по одному, у каждого — новый кейс (через генератор и стенд, с согласия пользователя) или юнит-тест. Параметры СОВ по редакциям, неизменность закрытого квартала, `run.sh` для запуска одной командой.

## Команды

```bash
uv sync                                              # зависимости
uv run pytest -q                                     # все тесты
uv run python -m sov.engine.cli tests/cases build/results && python3 tools/compare_golden.py build/results
uv run streamlit run app/main.py                     # интерфейс (с M3)
python3 tools/make_cases.py                          # пересобрать кейсы из генератора
python3 tools/template_harness/fill_and_recalc.py --case T05   # пересчитать эталон (нужен LibreOffice)
python3 tools/make_samples.py                        # пересобрать samples из кейсов
python3 tools/make_docs_tables.py                    # обновить таблицы в docs
```

Скрипты `tools/` используют только openpyxl; запускай их через `uv run python …`, если openpyxl нет в системном Python.

## Как работать

- Маленькие шаги: правило → тест → код → коммит. Не переписывай то, что уже зелёное, без причины.
- Каждое решение, которого нет в документах (имена таблиц, формат, толкование), — строкой в `docs/DECISIONS.md`.
- Расхождение с эталоном объясняй по шагам расчёта: какое значение, где, по какому правилу, какое ожидалось. Пример такого разбора — `docs/WORKED_EXAMPLE.md`.
- Тексты интерфейса — по-русски; имена в коде — по-английски; термины СОВ (ПБ, БГБ, К фин) в интерфейсе как в методологии.
- macOS: Python ставь через `uv python install 3.12`, не трогай системный. Если `soffice` не находится — путь `/Applications/LibreOffice.app/Contents/MacOS/soffice`.
