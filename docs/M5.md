# M5 — личные кабинеты и права

В боковой панели выберите роль и условную учётную запись.
Сотрудник T0002 видит только свои назначения. Руководитель T0003 видит
TP-T02, очередь 1, и сотрудников T0002/T0003. Разрешения задаёт локальный
`config/demo_access.json`: проекты и состав ФП перечислены явно, отсутствие
разрешения означает отсутствие доступа. Это демонстрационный вход, не SSO.

В кабинете есть ПБ и пулы, сроки и суммы вех с пояснениями, график частей финала,
проценты, подтверждённые начисления закрытых кварталов, условный прогноз и xlsx.
Дата выплаты не выдаётся за подтверждение оплаты: пока нет подтверждённых
записей «выплачено», соответствующий показатель показывает прочерк.
Прогноз предполагает закрытие оставшихся вех в срок при неизменном текущем NPV;
недостающие KPI остаются проблемами, а не заменяются придуманными значениями.

«Что если» доступно сотруднику только по своим назначениям. Историческое
моделирование, БГБ, загрузка и уход доступны Группе СОВ. Руководитель работает
в режиме чтения и выгружает выписки. Кабинетные сервисы не возвращают исходные
периоды БГБ, а xlsx содержит только разрешённое назначение без БГБ.

Права проверяются до чтения результата в согласованной транзакции. Подстановка
чужого ID в просмотр, сценарий или экспорт приводит к отказу. Просмотры
руководителем и скачивания журналируются; слайдеры сотрудника не меняют БД.
При смене личности черновики расчёта и сценариев очищаются.

Проверки включают права сервисов, содержимое JSON и xlsx, хэш БД при сценариях,
журнал просмотров и выгрузок, открытие обеих ролей и сброс в AppTest.
Используются только условные данные; переносимость Windows предусмотрена,
проверки выполнены пока на macOS.
