# План тестирования

Тестируем только на условных данных: кейсы `tests/cases`, шаблон `reference/template`, образцы `samples`. Реальные калькуляторы, ФИО, БГБ и NPV в разработку не попадают (ТЗ, раздел 10–11).

## 1. Уровни

Целевая платформа — Windows, также поддерживается macOS. Перед эксплуатацией
на Windows выполняются pytest, пакетный CLI, импорт xlsx/CSV, экспорт xlsx,
работа SQLite и полный сценарий квартала. Проверить кириллицу и пути с
пробелами. Пока проверки выполняются на Mac, результат Windows не считать
подтверждённым. На M6 проверить установку и запуск через `run.bat`.

| Уровень | Что | Источник ожиданий | Порог |
| --- | --- | --- | --- |
| Юнит | отдельные функции: К фин, множитель вехи, К срока этапа, множитель БС, дата выплаты, веса, нормирование РП, загрузка МП | `tests/unit/*.json` | коэффициенты 1e-9, даты точно |
| Эталоны | движок на кейсе целиком | `tests/golden/spec/*.json` | суммы 0,01 ₽, коэффициенты 1e-9, даты и статусы точно |
| Автоконтроли | проблемы и статусы на испорченных кейсах | `tests/autocontrol/cases.json` | коды проблем, `blocking`, статусы |
| Реестр | `samples/*` → загрузчики → реестр → движок → результат по `case_map.csv` | те же `tests/golden/spec` | как у эталонов |
| «Что если» | сценарий не меняет реестр; пересчёт ≤ 1 с; «цена дня»; сброс | свойства, раздел 4 | — |
| Интерфейс | панель и кабинет открываются, основные сценарии проходят | smoke-тесты Streamlit (`streamlit.testing`) | — |

Приёмка по ТЗ — 1 ₽ на сумму. Внутри разработки ждём 0,01 ₽: промежуточные значения не округляются, поэтому большее расхождение — ошибка правила, а не округления.

## 2. Как работать с эталонами

- Эталон по ТЗ — `tests/golden/spec`. Его считает LibreOffice в копии шаблона с правками P1–P7 и правилами O1–O3, S1–S3 (`docs/TEMPLATE_MAP.md`).
- `tests/golden/template` — текущая практика калькуляторов, для отчёта о расхождениях (`docs/TEMPLATE_VS_SPEC.md`), не для приёмки.
- Эталоны и шаблон руками не правятся. Новый кейс: дописать в `tools/make_cases.py` → `python3 tools/make_cases.py` → `python3 tools/template_harness/fill_and_recalc.py --case <ID>` (нужен LibreOffice) → проверить числа в `reference/examples/<ID>_spec.xlsx` → закоммитить кейс, эталон и пример вместе.
- Если тест не сходится с эталоном, сначала найди, какое правило расходится (`docs/CALC_RULES.md`), и спроси пользователя. Подгонять эталон под код нельзя.
- Сверка из командной строки: движок пишет результаты в `build/results/<ID>.json`, затем `python3 tools/compare_golden.py build/results`.

## 4. Свойства режима «что если»

1. Любой сценарий не меняет ни одной строки реестра (проверка: хэш файла БД до и после).
2. Сценарий без изменений даёт ровно текущий расчёт.
3. Пересчёт одного сотрудника по одному назначению ≤ 1 с (на M-серии Mac обычно на порядки быстрее).
4. «Цена дня» вехи = результат при факте на день раньше минус результат при плановом факте; у вехи на потолке 150% она 0 в сторону опережения; при просрочке 100 дней и больше 0.
5. Кейсы для проверки: T05 (сдвинуть факт вехи 3 → упирается в потолок), T06 (веха 3 при −120 дней → 0), T14 (NPV через полгода ниже финального → часть приостановлена), T10b (доля БС 60% → 95%: множитель 0,94 → 1), T15 (дата ухода позже — меняется остаток).

## 5. Порядок прохождения

1. Юнит-тесты зелёные.
2. Эталоны: сначала РУПК без особенностей (T01, T06, T09, T21, T22), затем КУПК (T02–T05, T07, T13, T14, T16), затем БС (T10a–c), МП (T11), особые (T08, T12, T13b, T15–T15c, T17, T17b, T18, T20).
3. Автоконтроли.
4. Реестр на `samples` — все кейсы через `case_map.csv`. Ставка в образце одна (16%), поэтому T16 и T20 (свои ставки по вехам) через реестр сравниваются только без процентов.
5. «Что если», интерфейс.
