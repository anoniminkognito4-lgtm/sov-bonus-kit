# Смена формул и параметров через панель

Дополнение к комплекту `sov-bonus-kit`. Положить в `docs/RULE_CHANGES.md`. Что добавить в `CLAUDE.md` и `docs/DECISIONS.md` — в разделе 9.

В системе нет формул в ячейках. Каждое число калькулятора считает правило движка (`CALC_RULES`) с параметрами действующей редакции. Поэтому «поменять формулу» значит выпустить **новую редакцию**: изменить параметр или вариант правила, посмотреть, у кого и на сколько изменятся суммы, и утвердить с датой начала действия. Редакция сразу действует на все калькуляторы, это и есть «общий коммит».

Пока рядом живут Excel-калькуляторы, ту же правку вносит в файлы инструмент массовой правки (раздел 7). Он оформляет порядок, по которому 20.10.2026 меняли К фин.

---

## 1. Пример: новая формула К фин (20.10.2026)

В калькуляторах К фин теперь считается так:

- если стартовый **и** текущий NPV **оба больше** 500 млн — отношение `NPV_тек / NPV_старт`;
- иначе правило низкого NPV: `1 + 0,05 × Δ / 100 млн`, если `|Δ| > 50 млн`, иначе 1;
- пределы прежние: 0,5–1,5 для КУПК (РП/ЗРП), 0,75–1,25 для КУПК.

В `CALC_RULES` §5 (правка P2) правило низкого NPV включается только по стартовому NPV < 500 млн. В старом шаблоне — по `|NPV_тек| < 500 млн`. Три варианта расходятся:

| NPV старт, млн | NPV тек, млн | Категория | `start_lt` (сейчас в `CALC_RULES`) | `abs_current_lt` (старый шаблон) | `any_le` (новая формула) |
| --- | --- | --- | --- | --- | --- |
| 600 | 300 | КУПК | 0,75 | 0,85 | 0,85 |
| 800 | 480 | КУПК (РП/ЗРП) | 0,60 | 0,84 | 0,84 |
| 500 | 700 | КУПК | 1,25 | 1,25 | 1,10 |
| 450 | 900 | КУПК (РП/ЗРП) | 1,225 | 1,50 | 1,225 |
| −11 966 | −6 356 | КУПК (РП/ЗРП) | 1,50 | 0,53 | 1,50 |
| 499,6 | 560,7 | КУПК | 1,03 | 1,12 | 1,03 |

- Последние две строки — примеры 1 и 2 со слайда 24 (3,8 до предела и 1,03). Новая формула даёт оба ответа, старый шаблон — ни одного.
- Проверено: ни один из 27 эталонов и ни один кейс `tests/unit/k_fin_cases.json` при новой формуле не меняется. Вариант `any_le` можно сделать основным без пересборки эталонов, а первые четыре строки таблицы — добавить юнит-кейсами.
- В системе это параметр `k_fin.low_npv_trigger` со значениями `start_lt`, `abs_current_lt`, `any_le` и порог `k_fin.low_npv_threshold = 500 000 000` (сравнения строгие, как в формуле).
- С какого квартала действует новая формула, подтверждает пользователь (раздел 9).

## 2. Три уровня изменения

| Уровень | Что меняется | Примеры | Как | Код |
| --- | --- | --- | --- | --- |
| 1. Параметр | число или таблица в правиле | 500 млн, 50 млн, 0,05 за 100 млн, пределы К фин, доля авансов 0,67, 60 дней, 100 дней, 90/10, таблица загрузки | Группа СОВ в панели, новая редакция | не меняется |
| 2. Вариант | заранее заложенное толкование | условие низкого NPV (§1), толкования И-1…И-9, в том числе два режима И-9 | переключатель в редакции | вариант уже есть в коде |
| 3. Новая логика | то, чего нет среди вариантов | новый коэффициент, новое условие выплаты | запрос агенту из панели (раздел 6), затем это уровень 2 | новый вариант, старый остаётся |

Все параметры и варианты описаны в каталоге `src/sov/engine/params.py`: имя, параграф `CALC_RULES` и слайд, описание по-русски, единица, допустимый диапазон, значение по умолчанию, какие правила его используют. Редактор в панели строится из каталога, поэтому новый параметр сразу виден в панели без отдельного экрана.

**Формула одной ячейки одного калькулятора не правится.** Ячейка — это правило для всех калькуляторов. Если поправить её в одном месте, получится скрытое исключение. Исключения оформляются ручными решениями (`manual_decision`, «ручной расчёт»), как и сейчас.

## 3. Превью калькулятора и «как посчитано»

Экран **«Калькулятор»** показывает любой калькулятор (проект, очередь, этап) в раскладке листа «калькулятор»:

- шапка;
- блоки сотрудников рядом, как колонки K–O, P–T…;
- строки 1–13, вехи, ключевая веха, части 50/25/25.

Значения берутся из результата движка и реестра. Раскладку строит тот же код, что делает выписку (`DATA_FORMATS` §6): один отрисовщик для экрана и для xlsx.

Выбор ячейки (щелчком или из списка показателей) открывает справа панель **«Как посчитано»**:

- правило: параграф `CALC_RULES`, слайд, редакция, вариант;
- формула в записи методологии с подставленными числами, например: «К фин = 1 + 0,05 × (480 − 800) / 100 = 0,84. Отношение не применяется: NPV тек 480 млн ≤ 500 млн. Пределы 0,5–1,5»;
- входы с источниками: «NPV старт — `start_npv`, загрузка №12, файл, дата», «NPV тек — `npv` 2026-Q3, загрузка №15»;
- адрес ячейки в Excel-калькуляторе (`O10`, `T10`…). На время параллельного расчёта — значение из файла, если оно загружено.

Кнопки: «Изменить параметр» открывает черновик редакции по этому правилу, «Запрос на изменение» — раздел 6.

**Как сделать.** Движок по флагу `explain=True` возвращает рядом с результатом трассировку: по каждому значению правило, редакцию, входы и шаги. Числа от флага не меняются, функция остаётся чистой. Тест сверяет, что пересчёт по трассировке даёт то же значение.

## 4. Редакции

| Таблица | Поля |
| --- | --- |
| `edition` (новая) | `id`, `title`, `valid_from` (начало квартала), `status` (`draft`, `active`, `retired`), `parent_id`, `basis`, `file_ref`, `author`, `created_at`, `approved_by`, `approved_at`, `legacy_patch` (раздел 7) |
| `sov_param` | `edition`, `name`, `value` (число, вариант или таблица в JSON). В редакции хранятся только изменённые параметры, остальное наследуется от родителя |

- **Какая редакция действует.** По рассчитываемому кварталу: активная редакция с самым поздним `valid_from`, не позже начала квартала.
- **Прогноз.** Суммы будущих кварталов считаются по последней активной редакции, статус «прогноз».
- **Закрытые кварталы не пересчитываются.** Их начисления лежат в снимке со своей редакцией. Если `valid_from` новой редакции раньше закрытого квартала, панель предупреждает: разница возможна только корректировкой в следующем квартале по решению `edition_retro_correction`.
- **Эталоны** (`tests/golden`) и юнит-кейсы считаются с явно заданной базовой редакцией `E0` (`CALC_RULES` как есть). У каждой новой редакции свои кейсы: `tests/editions/<id>/*.json`.

## 5. Порядок смены

1. **Черновик.** Из экрана «Правила и редакции» или из «Как посчитано». Указать параметр или вариант, основание (протокол, письмо, файл), квартал начала действия, комментарий.
2. **Примеры.** Юнит-кейсы правила прогоняются на черновике: таблица «пример → было → стало». Пользователь добавляет свои примеры (вход → ожидаемое), они сохраняются с редакцией как приёмочные.
3. **Влияние.** Движок считает все назначения открытого квартала и прогноз по действующей редакции и по черновику. На экране:
   - по сотруднику: что изменилось (К фин, суммы по вехам и частям, статусы), было, стало, разница;
   - итоги по блокам и проектам, число затронутых;
   - фильтр «только изменившиеся» и выгрузка в xlsx.
4. **Утверждение.** Роль Группа СОВ. Редакция становится активной. В журнал пишется запись со сводкой влияния, выгрузка влияния прикладывается файлом.
5. **После.** «Рассчитать» идёт по новой редакции. Большие изменения сумм ловит обычная проверка `AMOUNT_CHANGE_10PCT`. Сверка параллельного расчёта показывает калькуляторы, в которые правку ещё не внесли.
6. **Откат.** До закрытия квартала редакцию можно вывести из действия (`retired`) и пересчитать. После закрытия — только новой редакцией.

Проблемы: `EDITION_DRAFT_EXAMPLE_FAILED` (свой пример не сходится, утвердить нельзя), `EDITION_RETRO_CLOSED` (дата раньше закрытого квартала), `EDITION_LEGACY_PENDING` (идёт параллельный расчёт, а правка Excel не отмечена).

## 6. Уровень 3: новая логика

**Запрос на изменение.** Кнопка в панели собирает текст для агента и сохраняет его в `docs/change_requests/CR-NNN.md`:

- правило и что изменить словами;
- формулу из Excel, если она есть;
- не меньше трёх примеров с ожидаемыми числами: обычный, на границе, на пределе;
- квартал начала и основание.

Примеры условные, без ФИО и реальных NPV.

**Что делает агент:**

- добавляет **новый вариант** правила, не трогая старый: прошлые редакции считаются по-старому;
- добавляет юнит-кейсы из запроса;
- обновляет `CALC_RULES` и `DECISIONS`;
- показывает пользователю расхождения;
- после согласия вариант доступен в панели как уровень 2.

**Формулы-выражения** (не в первой версии). Для нескольких правил (К фин, К срока) вариант можно было бы задавать выражением в синтаксисе Excel:

- переменные по имени (`NPV_старт`, `NPV_тек`, `Δ`);
- разрешённые функции: `ЕСЛИ`, `И`, `ИЛИ`, `МИН`, `МАКС`, `ABS`;
- безопасный разбор без `eval`;
- включение только после того, как сошлись примеры и показано влияние.

Делать это стоит, только если логика меняется чаще пары раз в год: произвольная формула обходит тесты и проверку кода, и ошибка сразу попадает в выплаты.

**Формулы не генерирует ИИ.** Внешние ИИ-сервисы в приложение не подключаются (`CLAUDE.md`, правило 6).

## 7. Правка Excel-калькуляторов на время параллельного расчёта

Инструмент `tools/legacy_patch/` (командная строка) и экран «Правка файлов калькуляторов». Он оформляет порядок, по которому меняли К фин 20.10.2026 и раньше вносили К перевыставления затрат в калькуляторы БС.

1. **Задание** — файл `patches/<id>.json`:
   - имя листа (`калькулятор`);
   - как найти ячейку в каждом блоке. Либо по подписи: `Коэф.фин.результата этапа` в строке 10, значение — последняя колонка блока. Либо по адресу в первом блоке (`O10`) с шагом блока 5 колонок;
   - новая формула для первого блока. Для остальных блоков относительные колонки сдвигаются (O → T → Y → AD → AI), абсолютные ссылки остаются. Сдвиг — через `openpyxl.formula.translate.Translator` (это перевод текста формулы, файл openpyxl не сохраняет) или свой разбор;
   - какие варианты заменять (канонический вид) или «любую формулу»;
   - папки (с подпапками), фильтр имени (`bonus_`), исключения (`~$`, `завершен_` и т. п.).
2. **Обзор**, только чтение. По каждому файлу и блоку — канонический вид текущей формулы (колонки блока → `C0…C4`, пробелы вне кавычек убраны) и вариант:
   - новая;
   - известный старый вариант;
   - неизвестная;
   - значение вместо формулы;
   - общая (`shared`) формула или формула массива.
   Сводка по вариантам и папкам. Ничего не пишется.
3. **Пробный прогон** на одном файле. Пользователь открывает его в Excel.
4. **Копия.** Исходники копируются в папку бэкапа с подпапками. Существующие копии не перезаписываются (суффикс с датой и временем). Без успешной копии запись не начинается.
5. **Запись**, правкой XML:
   - в целевых ячейках заменить текст `<f>`, убрать `<v>` и `t`;
   - в `xl/workbook.xml` поставить `fullCalcOnLoad="1"`;
   - остальные части пакета — байт в байт.
   Пропускаются: открытые файлы (`~$`), файлы только для чтения, ячейки со значением вместо формулы (выплаченные), главная ячейка общей формулы с зависимыми ячейками и формулы массива (это «вручную»). По умолчанию результат пишется в отдельную папку с той же структурой. На месте — только с явным флагом и при готовой копии, как договорились для К фин.
6. **Проверка по файлу:**
   - перечитанная формула равна ожидаемой;
   - изменились только XML листа и `workbook.xml`;
   - хеш `vbaProject.bin` не изменился;
   - архив открывается.
7. **Отчёт** — CSV: файл, блок, ячейка, вариант «было», «стало», статус, причина. Плюс сводка.

**Превью для файлов.** На экране образцовый калькулятор пользователя (приложение читает его, ничего не пишет) показывается сеткой с формулами. Выбранная ячейка становится целью правки. Формула берётся из образца (его пользователь правит в Excel сам) или вводится. Дальше шаги 2–7.

**Одна правка — два места.** Пока идёт параллельный расчёт, у каждой редакции есть поле «Правка Excel»: номер задания или «не нужна». Если правку забыли, это покажет сверка параллельного расчёта.

Агент разрабатывает инструмент на условных копиях шаблона:

- варианты старой формулы и новая;
- значение вместо формулы и общая формула;
- файл-блокировка и файл только для чтения;
- калькуляторы с двумя и пятью блоками.

Реальные калькуляторы обрабатывает только пользователь.

## 8. Тесты

| ID | Что проверяет |
| --- | --- |
| E01 | каждый параметр `CALC_RULES` есть в каталоге. Редактор строится из каталога |
| E02 | наследование параметров. Выбор редакции по кварталу. Закрытый квартал не меняется |
| E03 | К фин: таблица §1 во всех трёх вариантах, примеры слайда 24 |
| E04 | эталоны зелёные с `E0`. Для `any_le` зафиксировано, что эталоны не меняются |
| E05 | влияние черновика: меняются только назначения КУПК с NPV из §1. Итоги и выгрузка |
| E06 | утверждение и вывод из действия, журнал, редакция в снимке квартала |
| E07 | трассировка: у каждого значения превью есть правило, входы и источники. Пересчёт по трассировке равен значению |
| E08 | обзор файлов: варианты распознаны на условных копиях |
| E09 | запись: изменились только нужные части. Значения, общие формулы, блокировки пропущены. Без копии записи нет. Запись на месте только с флагом |
| E10 | сдвиг формулы O → T → Y → AD → AI, абсолютные ссылки на месте |

**Готово, когда** тесты зелёные, а пользователь на условном реестре:

- переключил вариант К фин в черновике и увидел влияние;
- утвердил редакцию;
- в «Как посчитано» увидел новую формулу;
- на условной папке калькуляторов прошёл обзор, пробный прогон, запись и проверку.

| --- | --- |
| Формулы меняются только редакциями (параметр, вариант) с началом действия по кварталу; формула одного калькулятора не правится, исключения — ручными решениями | одна правка на все калькуляторы, без скрытых исключений |

| Внешние ИИ-сервисы в приложение не встраиваются | правило 6; ФИО, БГБ и NPV не должны покидать компьютер |
| Массовая правка Excel-калькуляторов — инструмент §7: правка XML, обзор и пробный прогон до записи, копия обязательна | порядок, проверенный на К фин и К перевыставления |
