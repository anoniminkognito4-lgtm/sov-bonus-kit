# Новый калькулятор с вехами из хранилища

Дополнение к комплекту `sov-bonus-kit`. Положить в `docs/NEW_CALC.md`. Опирается на `docs/MILESTONES.md` (хранилище вех). Что добавить в `CLAUDE.md` и `docs/DECISIONS.md` — в разделе 10.

В системе калькулятор — это не файл, а **этап очереди**: строка `stage`, зафиксированный набор вех этапа и команда (назначения). Кнопка «Новый калькулятор» создаёт этап и сразу собирает вехи из хранилища по тем же правилам, что макрос «Вставить вехи в новый калькулятор» (`ЗагрузитьВехи_ИзВыбранногоФайла`). Источник вех — хранилище, а не лист внутри файла. Остаётся проверить список и нажать «Создать».

Пока идёт параллельный расчёт, тот же набор можно выгрузить **файлом калькулятора** из шаблона пользователя: с заполненной шапкой, вставленными вехами и заполненным листом вех. Тогда не нужно вручную копировать выгрузку и запускать макрос (раздел 7).

---

## 1. Ограничения

Действуют все жёсткие правила `CLAUDE.md` и `docs/MILESTONES.md` §1. Дополнительно:

- Агент тестирует только на условном хранилище (`samples/milestones/`) и на шаблоне `reference/template/bonus_template_empty.xlsx`.
- Файл калькулятора из раздела 7 создаётся правкой XML копии шаблона. Шаблон не пересохраняется через openpyxl, pandas или LibreOffice, исходный шаблон не меняется, существующие файлы не перезаписываются.
- Реальный шаблон (`.xlsm`) пользователь указывает сам в настройках запущенного приложения. Агент его не открывает.

## 2. Калькулятор в системе

| Шапка шаблона | Что это в системе |
| --- | --- |
| `A1` проект | `project_code` (в файл пишется название из 1С) |
| `A2` очередь | очередь реестра (в файл пишется `queue_raw` из 1С) |
| `C16` этап | `stage` |
| `F1` переход из предыдущего этапа | `stage.continues_from_prev` |
| `F2` старт нового этапа | `stage.start_date` |
| `F3`, `G3` отношение к БС и доля перевыставления | признак проекта и `bs_share` |
| строки 16…ключевая | `calc_milestone`: набор вех и порядок |
| блоки сотрудников | назначения (`assignment`, `assignment_load`) |

В `TEMPLATE_MAP` проект указан в `B1`, так заполняет шаблон стенд эталонов. В рабочих калькуляторах и в макросах проект находится в `A1`, а очередь в `A2`. Файл из раздела 7 заполняет `A1` и `A2`.

Новая таблица `calc_milestone`:

| Поле | Что |
| --- | --- |
| `project_code`, `queue`, `stage` | калькулятор |
| `milestone_code` | веха |
| `order` | порядок строки (по плановой дате) |
| `source` | `queue` (веха очереди) или `project` (веха проекта без очереди) |
| `added_by` | создание калькулятора или решение `calc_set_change` |

## 3. Когда создаётся калькулятор

Система подсказывает, где нужен новый калькулятор. Это информационные проблемы на «Обзоре квартала»:

- в хранилище есть вехи этапа N+1 очереди, а калькулятора этого этапа нет, и до плановой даты ключевой вехи этапа N осталось меньше квартала (`NEWCALC_STAGE_DUE`);
- расстановка дала `RASST_NEXT_STAGE_MISSING` (`RASST` §7);
- в хранилище появились вехи нового проекта или новой очереди.

---

## 4. Отбор вех

### 4.1. Алгоритм (как макрос)

На входе: проект P, очередь Q и этап N.

1. **Кандидаты** — вехи проекта P этапа N с плановой датой и без решения `milestone_inactive`.
2. **Дата ключевой** — самая ранняя плановая дата среди ключевых вех очереди Q.
3. **Вехи очереди** — кандидаты очереди Q с любой датой, в том числе позже ключевой.
4. **Вехи проекта** — кандидаты без очереди с плановой датой не позже даты ключевой. Если ключевой нет, вехи проекта не берутся.
5. **Сортировка** по плановой дате, при равенстве — по порядку в выгрузке.
6. Ключевая веха идёт в строку ключевой, остальные — в строки 16 и ниже по порядку.

### 4.2. Чем система отличается от макроса

| Место | Макрос | Система |
| --- | --- | --- |
| несколько ключевых вех | молча берёт самую раннюю | так же, плюс вопрос `NEWCALC_MULTI_KEY` |
| ключевой вехи нет | вставляет остальные, строку ключевой оставляет пустой | `NEWCALC_NO_KEY`, блокирует |
| веха без плановой даты | молча пропускает | в списке, `MS_NO_PLAN_DATE` |
| веха очереди позже ключевой | вставляет в промежуточные строки | вставляет, плюс `NEWCALC_AFTER_KEY` |
| проект и очередь | сравнение текста после trim, с учётом регистра | сравнение кодов реестра. Если текст очереди в 1С и в калькуляторе отличается только пробелами или регистром — `NEWCALC_QUEUE_TEXT` (формула файла может не найти дату) |
| дубли наименования и очереди | формула берёт первую строку | `MS_DUPLICATE_KEY` блокирует |
| места в строках | 16…ключевая − 1. Что не поместилось — в сообщение | в системе ограничения нет. Для файла — `XLS_TOO_MANY_ROWS` |
| строка ключевой | ищется по цвету RGB 155, 194, 230 | в системе не нужна. Для файла — поиск по подписи (раздел 7) |
| статус вехи | не проверяет | снятые вехи и вехи с неизвестным статусом до решения `status_alias` не входят. Выполненные входят: по ним считаются авансы |

### 4.3. Состав фиксируется, даты обновляются

- Набор вех записывается в `calc_milestone` при создании калькулятора и сам **не меняется**. Плановые и фактические даты всегда берутся из хранилища, то есть из последней загрузки.
- Если после обновления хранилища отбор по п. 4.1 дал бы другой набор, появляется `NEWCALC_SET_CHANGED` с предложением добавить или убрать веху. Причины: новая веха, веха снята, веха перенесена в другой этап, сменилась ключевая.
- Применяется только решением `calc_set_change`. Новая веха меняет веса у всех, у кого она участвует (`CALC_RULES` §3). Как быть с уже выплаченными авансами, решает правило переноса вех (`CALC_RULES` §13). До его реализации назначения этапа получают статус «ручной расчёт».
- Сейчас так же: калькулятор меняется, только если кто-то заново запустит макрос.

## 5. Команда и загрузка

Шаг «Команда» предлагает назначения. Каждое из них применяется общим механизмом загрузки: предпросмотр, «Применить», журнал, откат.

- **Переход с предыдущего этапа.** Люди с живым назначением на этап N−1 той же очереди без даты ухода. Новое назначение начинается со дня после **своей** границы этапа N−1 (плановая дата ключевой вехи или индивидуальный срок), `from_prev_stage = true` (`RASST` §5.1).
- **Из расстановок.** Вопросы `RASST_NEXT_STAGE_MISSING` и `RASST_MISSING_ASSIGNMENT` по этой очереди после создания калькулятора пересчитываются и превращаются в предложения.
- **Вручную.** Добавить человека из `employee`.
- **Загрузка.**
  - Для ДРП, БС ОУС и БПСК — из таблицы загрузки по должности и этапу (`CALC_RULES` §2, D-061).
  - Для МП — по правилу сл. 20: один проект 100%, два и больше — по 50%, в том числе на дострое (D-063).
  - Для КУПК — из набора проектов РП и нормирования (`CALC_RULES` §2).
  - Заглушек «РП 100%, МП 50%», как в книге «Данные», нет. Нет загрузки — `ASSIGNMENT_INCOMPLETE`.
- **КУПК.** Стартовый NPV фиксируется на старт этапа (сл. 22–23). Нет значения — `NPV_MISSING`.
- **Старт этапа (`F2`).** По умолчанию — день после плановой даты ключевой вехи этапа N−1. Значение можно изменить, основание пишется в журнал.

## 6. Экран «Новый калькулятор»

Открывается из «Проектов» и из подсказок раздела 3.

1. **Шапка.** Проект, очередь, этап, переход из предыдущего этапа, старт этапа, БС. Если калькулятор для этой тройки уже есть — `NEWCALC_EXISTS`, создать нельзя.
2. **Вехи.** Таблица в виде строк калькулятора:
   - номер строки, этап, наименование, очередь или корпус;
   - плановая дата, факт, статус;
   - источник (очередь или проект);
   - пометки проблем.
   Ключевая веха — отдельной строкой внизу. Ниже — вехи, которые не вошли, с причиной: позже ключевой, без даты, снята, другой этап.
3. **Команда.** Предложения раздела 5 с флажками.
4. **«Создать».** Этап, набор вех и выбранные назначения записываются одной операцией в журнал. Её можно откатить, пока по этапу нет начислений в закрытом квартале.

После создания калькулятор виден в «Проектах», в превью калькулятора (`docs/RULE_CHANGES.md` §3) и в выписке (`DATA_FORMATS` §6). На том же экране есть кнопка «Файл для параллельного расчёта» (раздел 7).

## 7. Файл калькулятора для параллельного расчёта

Нужен, пока рядом с системой живут Excel-калькуляторы. Файл повторяет результат двух макросов сразу: «Загрузить вехи во все калькуляторы» заполняет лист вех, «Вставить вехи в новый калькулятор» — строки вех.

**Настройка.** Путь к шаблону по каждому блоку (БПП, БПСК, ДРП, БС), папка для новых файлов и шаблон имени (по умолчанию `bonus_<проект>_<очередь>_<этап>`, расширение как у шаблона).

**Что пишется** в копию шаблона, только правкой XML:

| Где | Что |
| --- | --- |
| `калькулятор!A1`, `A2` | название проекта и очереди **как в 1С** (`Проект`, `queue_raw`): по ним формулы ищут даты |
| `калькулятор!C16` | номер этапа |
| `калькулятор!C`, `E`, `F`, строки 16…ключевая | сначала очистить, как макрос, затем номер этапа, наименование и очередь вех по порядку. Ключевая — в строку ключевой. Для вписанных строк снять `hidden` |
| `F1`, `F2`, `F3`, `G3` | если заданы на шаге 1 |
| `Лист для загрузки вех!B3:V` | очистить, затем все вехи проекта (все очереди и этапы, как копирует макрос). Для каждой вехи — её последняя строка выгрузки (`milestone_raw_row`) в порядке выгрузки, **даты текстом `ДД.ММ.ГГГГ`**: формула `G` читает их через `DATEVALUE` |
| `xl/workbook.xml` | `fullCalcOnLoad="1"`: Excel пересчитает книгу при открытии |

**Правила записи:**

- Строки пишутся как inline-строки, чтобы не трогать `sharedStrings.xml`. Стиль ячейки (`s`) сохраняется. Колонку A листа вех (формула ключа) не трогать.
- Остальные части пакета копируются побайтно, в том числе `vbaProject.bin`. Если в C, E или F строк вех оказалась формула, она не трогается: `XLS_UNEXPECTED_FORMULA`.
- **Строка ключевой** ищется по подписи `Финальный бонус без накопленных процентов` в колонке M первого блока. Цвет — только проверка. В части старых калькуляторов цвет строки другой (тема 7 вместо темы 4 со светлотой +40%), и макрос там отказывается вставлять вехи. Подписи нет — `XLS_KEY_ROW_NOT_FOUND`, файл не создаётся.
- Места для промежуточных вех — строки от 16 до строки ключевой − 1: в шаблоне 20, в маленьких калькуляторах меньше. Что не поместилось — `XLS_TOO_MANY_ROWS` со списком, как в сообщении макроса.

**Самопроверка** перед сохранением. Повторить формулы файла на Python:

- ключ `E & " " & F` по каждой вписанной строке;
- поиск по `C & " " & H` листа вех только в пределах строк, где в колонке A есть формула ключа.

По каждой строке показать дату, которую найдёт Excel. Не нашлась (вне диапазона формулы, расхождение текста, дубль) — `XLS_LOOKUP_MISS`.

**Проверка готового файла:**

- архив открывается;
- изменились только `xl/workbook.xml` и XML двух листов;
- остальные части совпадают байт в байт.

Если файл с таким именем уже есть — `XLS_FILE_EXISTS`, ничего не пишется. Каждое создание — строка лога: файл, шаблон, калькулятор, сколько вех вписано и не поместилось, результат самопроверки.

**Чего файл не делает.** Команду в файл не вносит: блоки сотрудников, как и сейчас, заполняет макрокнига из «Истории». Существующие калькуляторы не меняет. Для массовой вставки вех в существующие файлы остаётся макрос «Вставка вех по папкам» (`modVehiPapki`). Он, как и исходный макрос, ищет строку ключевой по цвету, поэтому калькуляторы с другим цветом пропускает с записью в лог.

Первый запуск на реальном шаблоне пользователь проверяет сам: открывает файл в Excel и сверяет даты с самопроверкой. Так же проверяли правку К фин.

## 8. Проверки: коды проблем

| Код | Блокирует | Что обнаружено |
| --- | --- | --- |
| `NEWCALC_EXISTS` | да | калькулятор для этой тройки уже есть |
| `NEWCALC_NO_KEY` | да | у очереди и этапа нет ключевой вехи |
| `NEWCALC_MULTI_KEY` | нет, вопрос | несколько ключевых вех, взята самая ранняя |
| `NEWCALC_AFTER_KEY` | нет | веха очереди позже ключевой |
| `NEWCALC_QUEUE_TEXT` | нет | текст очереди отличается пробелами или регистром |
| `NEWCALC_SET_CHANGED` | нет, до решения | отбор дал бы другой набор вех (п. 4.3) |
| `NEWCALC_STAGE_DUE` | нет | пора создать калькулятор следующего этапа (раздел 3) |
| `XLS_KEY_ROW_NOT_FOUND` | да, файл | в шаблоне не найдена строка ключевой |
| `XLS_TOO_MANY_ROWS` | нет | вех больше, чем строк |
| `XLS_LOOKUP_MISS` | нет | формула файла не найдёт дату |
| `XLS_UNEXPECTED_FORMULA` | нет | формула там, где ждали значение |
| `XLS_FILE_EXISTS` | да, файл | файл с таким именем уже есть |

Решение `calc_set_change`: `{"calc":"TP-07/1/5","add":["TP-07/1/5/0014"],"remove":[]}` с основанием.
