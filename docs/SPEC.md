> Копия ТЗ из Claude Docs (ревизия 95, 14.10.2026). Схема архитектуры из документа заменена текстовой.
> Для движка точнее `docs/CALC_RULES.md`; при расхождении с ТЗ — спроси пользователя.


## 1. Цель и границы

Система заменяет Excel-калькуляторы проектных команд (сейчас 164 калькулятора на 286 сотрудников) единым расчётом. Данные хранятся в одном реестре, считает один движок по правилам СОВ, Группа СОВ управляет всем через панель, а сотрудник видит свой бонус в личном кабинете.

**Основа расчёта:** СОВ проектных команд, редакция v2 с 3 квартала 2026 (далее «СОВ», ссылки на слайды по этой редакции), плюс согласованная правка по К перевыставления затрат в БС (раздел 6.6).

**В объёме первого этапа**

- Виды СОВ: «Вехи», «Вехи от NPV», «Вехи от KPI», «вр. KPI (Вехи)».
- Блоки: БПП ОУП, БРП ДРП, БПСК ДУП и ГАП, БС ОУС.
- Категории: КУПК (РП/ЗРП), КУПК, РУПК, МП ОУП.

**Второй этап:** вид СОВ «KPI (Вехи от NPV)» (сейчас 46 калькуляторов): расчёт веса проектов с ограничением min/max.

**Вне объёма:** коммерческий блок, Проектное бюро, бонус за покупку проектов, Группа завершения проектов (тип «KPI»). Для них нужна своя методология и ответы на открытые вопросы из исходного ТЗ.

**Обязательные принципы**

- Правила СОВ хранятся по редакциям: расчёт за период идёт по редакции, действовавшей в этот период.
- Любой расчёт воспроизводим: по сотруднику видно, из каких данных и по какой редакции получена каждая сумма.
- Выписка для проверки сохраняет привычный вид калькулятора: вехи, даты, коэффициенты, суммы.

## 2. Пользователи и роли

Расчётом управляет только Группа СОВ. Остальные роли смотрят результат в своих границах.

| Роль | Кто | Что делает | Что видит |
| --- | --- | --- | --- |
| Администратор расчёта | Группа СОВ | Загружает данные, разбирает проблемы, вносит ручные данные и правки с основанием, запускает расчёт, закрывает квартал | Всех сотрудников, проекты, суммы, журнал |
| Руководитель ФП, РП | РП БПП, РПП, РПС, РППП, Директор деп. экспертизы АР | Согласует выписки, предлагает перераспределение ±30% для РУПК своего ФП | Выписки по своим проектам и своему ФП |
| Сотрудник | КУПК, РУПК, МП | Смотрит свой расчёт и статусы сумм | Только свои назначения, вехи, коэффициенты и суммы |
| Администратор системы | HRIT | Интеграции, права доступа, справочники | Настройки, без доступа к суммам бонусов |

Режим «что если» входит в первую версию (раздел 9.4): сотрудник и Группа СОВ подставляют свои значения и сразу видят сумму к выплате. Результаты моделирования помечены и нигде не сохраняются.

## 3. Архитектура

Система состоит из четырёх слоёв: источники, реестр с загрузкой, движок расчёта и интерфейсы. Движок не хранит и не правит исходные данные: он читает реестр и записывает туда начисления.

```
Источники (1С IHR, 1С УП ШР, «Мотивационные вехи», «Мотивационный NPV», KPI, ПТО БС, ЦБ, ручные решения)
   │  загрузка с предпросмотром и журналом
   ▼
Реестр (SQLite в прототипе → БД / DWH): сотрудники, БГБ, проекты, этапы, вехи, назначения, NPV, параметры СОВ, начисления, журнал
   │  чтение                         ▲ запись начислений
   ▼                                 │
Движок расчёта (чистые функции, правила СОВ по редакциям) ──┘
   │
   ▼
Интерфейсы: панель Группы СОВ · личный кабинет · «что если» · выгрузки Excel и файл к начислению
```

Интерфейсы показывают то, что лежит в реестре. Правки идут только через загрузку или ручные решения в панели, и каждая попадает в журнал. На пилоте реестр может быть Excel-файлом; панель и движок делаются так, чтобы его можно было заменить на базу данных или DWH без переделки.

## 4. Модель данных реестра

Реестр хранит каждое исходное значение один раз, с источником и датой действия. Проекты сопоставляются по коду из 1С, по названию ничего не связывается. **Сотрудники — по ФИО с внутренним номером: табельного номера нет** (D-101, заменяет прежнее правило для сотрудников); неоднозначное — вопрос, не догадка.

| Таблица | Одна строка | Ключевые поля | Откуда |
| --- | --- | --- | --- |
| Сотрудники | сотрудник | таб. номер, ФИО, должность, подразделение, дата приёма и увольнения, окончание ИС и его итог | 1С IHR, УП ШР |
| История БГБ | период действия БГБ | таб. номер, БГБ, дата с, дата по | 1С IHR |
| Проекты и очереди | очередь проекта | код, название, очередь/корпус, участвующие блоки, признак проекта-исключения (сл. 37, 39), дата продажи, дата передачи в Группу завершения | 1С |
| Этапы | этап очереди | номер 1–5, дата начала, ключевая веха, признак достроя | 1С |
| Вехи | веха этапа | наименование, ключевая да/нет, плановая дата (все версии с датой и основанием переноса), фактическая дата (MSP), дата закрытия в 1С, статус | 1С «Мотивационные вехи» |
| Назначения | сотрудник × очередь × этап | вид СОВ, категория (КУПК (РП/ЗРП), КУПК, РУПК, МП), должность на проекте, дата начала и окончания, причина окончания | 1С УП ШР (проектные роли) |
| Индивидуальные сроки | сотрудник × веха | индивидуальная плановая дата, основание | 1С «Мотивационные вехи» |
| NPV | проект × месяц × версия ФМ | NPV с плановыми и с прогнозными ПАУР, дата утверждения ФЮБ | 1С «Мотивационный NPV» |
| Стартовый NPV | назначение КУПК | значение, дата фиксации, корректировки с основанием (сл. 22–23) | расчёт + Группа СОВ |
| Загрузка | должность × этап | % загрузки (сл. 18); отдельно нормирование РП и ЗРП (сл. 19) | СОВ |
| Перевыставление БС | проект × квартал | % переданных к перевыставлению затрат | отчёт ПТО БС |
| KPI МП | сотрудник × квартал | % выполнения KPI | 1С, задачи KPI |
| Перераспределение | сотрудник × веха | % изменения (±30%), кто решил, дата согласования | решение РФП |
| Ключевая ставка ЦБ | период | ставка, дата с | сайт ЦБ, вручную |
| Параметры СОВ | редакция × параметр | доля авансов, пределы К фин, +50%, порог 100 дней, норматив 90% и т. д. | Группа СОВ |
| Начисления | сумма по сотруднику и вехе | тип (аванс, финал, часть 50/25/25, остаток при уходе, проценты), сумма, квартал, статус, редакция правил | движок |
| Журнал | изменение | кто, когда, что было, что стало, основание | система |
| Набор проектов РП | РП × проект или очередь | ранг РП, класс, площадь ВНС, этап, доп. объекты, признаки очереди и логистического центра, дата утверждения | форма фиксации, утверждённая ДП или ВП БПП |

Плановые даты вех и параметры СОВ хранятся со всей историей, а не только текущее значение: уже выплаченные авансы считались по старым датам и правилам.

## 5. Источники данных и загрузка

Данные попадают в реестр только через загрузку с предпросмотром изменений или через ручную правку с основанием. Править базу напрямую нельзя.

| Источник | Что берём | Когда |
| --- | --- | --- |
| 1С IHR | БГБ и его изменения, должности, приём, перевод, увольнение, ИС | ежедневно или кнопкой |
| 1С УП ШР, рабочий стол «Проектные команды» | назначения на проекты, проектные роли, даты начала работы, % загрузки этапа | ежедневно или кнопкой |
| 1С, справочник «Мотивационные вехи» | вехи, плановые и индивидуальные сроки, фактическая дата MSP, дата закрытия в 1С, статус | ежедневно или кнопкой |
| 1С, отчёт «Мотивационный NPV сотрудников» | NPV по проектам по версиям ФМ | после утверждения ФМ в ФЮБ (до 10 раб. дней после месяца) |
| 1С, задачи KPI | % выполнения KPI МП и «вр. KPI (Вехи)» | по итогам квартала |
| Отчёт ПТО БС (файл по шаблону) | % переданных к перевыставлению затрат по проектам | до 15 числа месяца после квартала |
| Сайт ЦБ | ключевая ставка | при изменении ставки |
| Группа СОВ, вручную | перераспределение ±30%, корректировки стартового NPV, решения ВП БПП и Президента | по событию |

На первом этапе допустима загрузка выгрузок файлами. Формат выгрузки вех совпадает с текущим листом шаблона «Лист для загрузки вех» (Статус, Наименование, Шаблон, Ключевая, Вид, Проект, Очередь, Этап, Заказчик, Исполнитель, Плановый срок…).

**Порядок загрузки любого файла**

1. Система определяет тип файла по заголовкам и проверяет структуру: обязательные колонки, форматы дат и чисел.
2. Строки сопоставляются с реестром по ключам (таб. номер, код проекта, код вехи). Несопоставленные строки попадают в список разбора, а не в реестр.
3. Группа СОВ видит предпросмотр: сколько записей добавится, изменится и не распознано, с открытием каждой строки.
4. После «Применить» изменения записываются в реестр и в журнал с именем файла и автором.
5. Повторная загрузка того же файла ничего не меняет. Любую загрузку можно откатить до закрытия квартала.

## 6. Правила расчёта

Движок считает по правилам ниже. Где шаблон калькулятора сейчас считает иначе, расхождение и принятое решение указаны в разделе 11. Промежуточные значения не округляются, как и в калькуляторах; до копеек округляется только сумма к выплате.

### 6.1 Дата начала работы на этапе

- Новый участник проекта: дата назначения из 1С УП ШР.
- Переход проекта в следующий этап: день после плановой даты ключевой вехи предыдущего этапа, с учётом индивидуального срока сотрудника по этой вехе (сл. 9).
- По блокам (сл. 56): БПП ОУП, БРП ДРП, БПСК ДУП и ГАП — с даты решения о начале проекта; БС, кроме РПС, — с фактической даты вехи «Получено РнС»; РПС — с фактической даты ключевой вехи 1 этапа.

### 6.2 Проектный бонус (ПБ)

```latex
\text{ПБ} = \sum_{i} \frac{\text{БГБ}_i}{365} \times \text{дни}_i \times \text{К}_{\text{загр},\,i}
```

- Период i — отрезок, на котором БГБ и К загрузки не менялись; дни считаются включительно.
- Длительность этапа = плановая дата ключевой вехи (или индивидуальный срок) − дата начала + 1.
- К загрузки:
  - по должности и этапу из таблицы СОВ (сл. 18);
  - РП ОУП БПП: по нормированию загруженности, см. ниже; для ЗРП правило не задано (сл. 14, 19, раздел 13);
  - МП ОУП: норма 2 проекта; на одном проекте 100%, на двух и более по 50% на проект (сл. 20);
  - несколько очередей одного проекта: % этапа ÷ число очередей; если суммарная загрузка сотрудника меньше 100%, она пропорционально приводится к 100%, иначе берётся фактическая (сл. 14–17).
- Доля ПБ на авансы: 67% на 1–4 этапах, 33% на 5 этапе (сл. 9).

**Нормирование загрузки РП ОУП БПП** (файл «Нормирование загруженности РП ОУП БПП», 1 кв. 2026)

```latex
\text{К}_{\text{сложн}} = \text{К}_{\text{класса}} \times \text{К}_{\text{площади}} \times \text{К}_{\text{этапа}} + 0{,}05 \times \text{доп. объекты}
```

| Параметр | Коэффициенты |
| --- | --- |
| Класс | Элит 1,1 · Премиум 1,0 · Бизнес и Бизнес+ 0,9 · Комфорт 0,8 |
| Площадь (м² ВНС, включая ДОО и СОШ) | S 1,0 · M 1,2 · L 1,3 · XL 1,4 · XXL 1,5 |
| Этап | 1 — 0,4 · 2 — 0,4 · 3 — 0,6 · 4 — 0,6 · 5 — 0,3 |
| Доп. объект | +0,05 за каждый: ДОО и СОШ для города, линейный объект, ОКН и ИЦГФО, ливневая насосная, ЛОС; другие по согласованию с ДП |

| Размер, тыс. м² | S | M | L | XL | XXL |
| --- | --- | --- | --- | --- | --- |
| Элит | < 20 | 20–50 | 51–80 | 81–100 | > 100 |
| Премиум | < 50 | 50–100 | 101–200 | 201–300 | > 300 |
| Бизнес и Бизнес+ | < 50 | 50–100 | 101–200 | 201–300 | > 300 |
| Комфорт | < 100 | 100–200 | 201–300 | 301–400 | > 400 |

- Очереди начиная со 2 этапа считаются отдельными проектами, их коэффициент вместе с надбавкой за доп. объекты умножается на 0,85. БЦ, ТЦ и ФОК — отдельные очереди с классом проекта. Логистический центр — произведение основных коэффициентов × 0,7.
- Итоговая загрузка РП x — сумма коэффициентов по всем проектам и очередям. Берётся точное произведение, как в примерах файла; матрица на слайде 6 округлена до 0,1 и нужна только для ориентира.
- % загруженности для ПБ: если x не больше y, то 100%; иначе (x ÷ y − 1) × 2 + 1. Порог y: 1 ранг — 1,2; 2 ранг — 1,0; 3 ранг — 0,8.
- К загрузки на проект = % загруженности ÷ число проектов и очередей в работе (СОВ, сл. 14, 19). Пример: РП 1 ранга, Элит XXL этап 1 (0,66) и Премиум M этап 4 (0,72): x = 1,38, загруженность 130%, на каждый из двух проектов 65%.
- До 01.01.2026 действовал коэффициент количества проектов, поэтому ПБ этапа, начатого раньше, считается двумя периодами (СОВ, сл. 19).
- Набор проектов и доп. объектов РП фиксирует формой и утверждает с ДП или ВП БПП; в реестре это отдельная таблица с датой утверждения.
- Допустимая загрузка (1 ранг 1,0–1,4; 2 ранг 0,8–1,2; 3 ранг 0,6–1,0) на расчёт не влияет и используется как автоконтроль.

### 6.3 Веса вех

- Ключевая (финальная) веха веса не имеет; остальные вехи сотрудника весят одинаково: 100% ÷ их число (сл. 13).
- Вехи с плановой датой (с учётом индивидуального срока) в первые 60 календарных дней работы на этапе в расчёт не входят (в СОВ — «2 месяца», во всех калькуляторах — 60 дней), их вес делится между остальными (сл. 55). Не применяется, если сотрудник перешёл из предыдущего этапа того же проекта.

### 6.4 К срока

```latex
\text{К}_{\text{срока}} = 1 + (\text{план} - \text{факт}) \times 1\%
```

- план — плановая дата или индивидуальный срок; факт — фактическая дата (MSP); дни календарные. Опережение увеличивает коэффициент, просрочка уменьшает.
- К срока не меньше 0: при просрочке 100 дней и больше бонус за веху равен 0.
- Промежуточная веха: К срока не больше 1,5; ограничение применяется до умножения на К фин, то есть бонус не больше 150% бонуса за веху в срок (сл. 13).
- Ключевая веха: К срока этапа по той же формуле, без ограничения 1,5. При опережении этапа больше чем на 100 дней сумма получает статус «требует решения ВП БПП и Президента» (сл. 13).

### 6.5 К финансового результата (только КУПК)

```latex
\text{К}_{\text{фин}} = \frac{\text{NPV}_{\text{тек}}}{\text{NPV}_{\text{старт}}}
```

- Пределы: РП и ЗРП БПП — от 0,5 до 1,5; остальные КУПК — от 0,75 до 1,25 (сл. 21).
- Стартовый NPV меньше 500 млн или отрицательный: К = 1 + 0,05 × (NPV тек − NPV старт) ÷ 100 млн; при разнице не больше 50 млн К = 1; пределы те же. Так посчитан пример 2 на сл. 24: стартовый 499,6 млн, текущий 560,7 млн, К = 1,03.
- NPV текущий — по ФМ отчётного квартала, в котором закрыта веха, после утверждения ФЮБ (сл. 21). До утверждения сумма имеет статус «прогноз».
- NPV стартовый свой у каждого КУПК (сл. 22–23): с начала 1 этапа — ФМ ИК-Покупка; при переходе в следующий этап — ФМ квартала завершения предыдущего; при выходе на проект в процессе — ФМ на конец месяца выхода. Не меняется при смене должности внутри проекта. Корректируется при смене ставки дисконтирования, методики ПАУР, продлении этапа и по решению Президента или ВП БПП.

### 6.6 К перевыставления затрат (БС, КУПК и РУПК)

```latex
\text{К}_{\text{пер}} = \min\bigl(1;\ \max(0;\ (\text{доля} - 40\%) \times 2)\bigr),\qquad \text{множитель} = 90\% + 10\% \times \text{К}_{\text{пер}}
```

- Доля — переданные к перевыставлению затраты ÷ все затраты к перевыставлению, накопительно с начала учёта (декабрь 2025) по последний рабочий день квартала (сл. 26). При доле 90% и выше К = 1.
- Множитель применяется к авансам, финальному бонусу и остатку при уходе. Правка 90/10 уже действует и внедряется в первой версии; в тексте СОВ (сл. 10, 12, 26) её пока нет.

### 6.7 Аванс за промежуточную веху (сл. 10, 12)

| Категория | Формула |
| --- | --- |
| КУПК, КУПК (РП/ЗРП) | доля авансов × ПБ × вес × К срока × К фин × множитель БС |
| РУПК | доля авансов × ПБ × вес × К срока × множитель БС |
| МП, «вр. KPI (Вехи)» | доля авансов × ПБ × вес × К срока × (KPI − 50%) × 2 |

- KPI — из 1С за квартал; если аванс не выплачивался несколько кварталов, берётся среднее за эти кварталы (сл. 10).
- Если предыдущая по плану веха не закрыта в 1С, аванс за следующую считается, но не выплачивается (сл. 25).
- Квартал начисления — квартал закрытия вехи в 1С (сл. 9). Выплата — 10 числа второго месяца после квартала, после отчётной сессии; если 10 число выходной — в предыдущий рабочий день (так в калькуляторах: 08.08.2025, 08.05.2026). Исключение (сл. 25): веху, подтверждённую в 1С после сессии, но закрытую датой прошлого квартала, начисляют вне сессии, в ближайший день выплаты зарплаты.

### 6.8 Финальный бонус (ключевая веха)

| Категория | Формула |
| --- | --- |
| КУПК, КУПК (РП/ЗРП) | ПБ × К срока этапа × К фин × множитель БС − выплаченные авансы |
| РУПК | ПБ × К срока этапа × множитель БС − выплаченные авансы |
| МП, «вр. KPI (Вехи)» | ПБ × К срока этапа × (средний KPI за этап − 50%) × 2 − выплаченные авансы |

- Отрицательный финальный бонус равен 0. Если он вместе с процентами на отложенную часть меньше 0, проценты не выплачиваются; антибонус на следующий этап не переносится (сл. 11).
- Выплата (сл. 25, 28): РУПК и МП — 100% по итогам квартала завершения этапа. КУПК на 1–4 этапах — 50% сразу, 25% через квартал и 25% через полгода, если NPV не ниже финального NPV этапа (при равенстве часть выплачивается). Если упал — выплата приостанавливается и возобновляется, когда NPV вернётся; если не вернулся к концу проекта, невыплаченная часть сгорает. На 5 этапе КУПК, кроме РП и РПС, получают 100% сразу; РП и РПС при оставшейся расходной части — 50% и 50% через 2 квартала; если расходы превысили ФМ, вторые 50% умножаются на К соблюдения расходной части = плановый бюджет затрат ÷ фактический, не больше 1 (сл. 28).

### 6.9 Отложенная часть и проценты (сл. 11, 72)

- Каждый выплаченный аванс откладывает часть ПБ: аванс ÷ доля авансов × (1 − доля авансов); на 1–4 этапах это аванс ÷ 67% × 33%, на 5 этапе — аванс ÷ 33% × 67% (подтверждено; в действующих калькуляторах 5 этапа стоит ÷ 67% × 33%, их нужно исправить).
- На каждую часть отдельно начисляются проценты: часть × средневзвешенная ключевая ставка ЦБ ÷ 365 × дни от выплаты аванса до выплаты финальной части.
- У КУПК проценты делятся на три выплаты 50/25/25, каждая со своим сроком индексации. Ставка считается системой из истории ставок, а не вводится вручную.

## 7. Особые случаи

Особые случаи входят в первый этап, кроме отмеченных «этап 2». До их реализации сотрудник с таким случаем помечается статусом «ручной расчёт» и не считается автоматически.

| Случай | Правило | Слайд |
| --- | --- | --- |
| Увольнение или перевод с проекта | Вехи, закрытые в 1С до даты ухода, оплачиваются в обычные сроки; аванс за веху после ухода не платится. Остаток = ПБ ÷ плановая длительность этапа × отработанные дни × К срока этапа × К фин (КУПК) или (KPI − 50%) × 2 (МП) × множитель БС − выплаченные авансы. К фин — по меньшему из NPV на дату ухода и после завершения этапа. Если этап закрыт с опережением уже после ухода, К срока этапа = 1. Остаток платится после завершения этапа. Уволенным за грубое нарушение бонус не платится (признак ставит Группа СОВ). | 47–48 |
| Перевод РУПК в КУПК | Новое назначение с даты перевода: свой ПБ и появляется К фин. Предыдущее назначение закрывается как перевод. Стартовый NPV — по ФМ на конец месяца перевода, как у сотрудника, вышедшего на проект в процессе этапа (сл. 22). | исходное ТЗ |
| Испытательный срок | ПБ формируется с первого дня, но выплаты ждут успешного окончания ИС. Если ИС не пройден, бонус за закрытые вехи и отложенная часть не выплачиваются. | 55 |
| Перераспределение ±30% (только РУПК) | РФП меняет бонус сотрудника за веху не более чем на 30%, сумма по ФП и проекту не меняется; до нуля снижать нельзя, себе менять нельзя, один РУПК в ФП — нельзя. Финальный бонус умножается на К перераспределения = 100% + сумма процентов перераспределения ÷ число вех, выполненных в период работы. | 31–32 |
| Продажа проекта | Дата окончания работы задаёт РП, не позже первого платежа по ДКП (+ до 14 дней по согласованию). Остаток = ПБ ÷ плановая длительность × отработанные дни × К фин прошлого квартала (КУПК) − авансы; выплата по итогам квартала продажи. | 37–38 |
| Передача в Группу завершения до конца 5 этапа | Оставшийся ПБ не выплачивается. | 9 |
| Перенос вех и продление этапа | Новая плановая дата записывается новой версией с основанием. Длительность и ПБ увеличиваются на срок продления; выплаченные авансы не пересчитываются, разница уходит в финальный бонус. Не применяется к ВП, директорам и начальникам отделов. | 61–63, FAQ |
| Расходная часть на 5 этапе (РП, РПС) | Если расходы превысили ФМ, вторые 50% умножаются на К соблюдения расходной части = плановый бюджет затрат ÷ фактический бюджет затрат, не больше 1. | 28 |
| Проекты-исключения БС и отложенные бонусы по старой СОВ | Считаются по правилам предыдущих редакций, с коэффициентом количества проектов. Этап 2. | 39, 45 |

## 8. Статусы сумм и автоконтроли

У каждой суммы есть статус, и сотрудник всегда видит его рядом с цифрой. Без статуса онлайн-расчёт в середине квартала будут принимать за обещание выплаты.

| Статус | Когда |
| --- | --- |
| Прогноз | веха не закрыта в 1С, или ФМ квартала ещё не утверждена, или нет KPI за квартал |
| Ждёт предыдущую веху | веха закрыта, но предыдущая по плану — нет (сл. 25) |
| К начислению | все данные квартала есть, расчёт на согласовании |
| Начислено | квартал закрыт Группой СОВ, сумма ушла в файл к начислению |
| Выплачено | наступила дата выплаты |
| Приостановлено | части 25% КУПК, если NPV ниже финального NPV этапа |
| Сгорело | NPV не вернулся к концу проекта; ИС не пройден; передача в Группу завершения |
| Ждёт окончания ИС | сотрудник на испытательном сроке |
| Требует решения | опережение этапа больше 100 дней: расчётная сумма видна, но не выплачивается до решения ВП БПП и Президента |
| Ручной расчёт | случай, который движок пока не считает (раздел 7) |

**Автоконтроли.** Перед расчётом система проверяет данные и выдаёт список проблем. Расчёт по сотруднику с блокирующей проблемой не попадает в файл к начислению.

| Проверка | Блокирует |
| --- | --- |
| У КУПК нет NPV стартового или текущего за квартал закрытия вехи | да |
| Назначение без категории, вида СОВ или % загрузки | да |
| Нет БГБ на какой-то период работы на этапе | да |
| У этапа нет ключевой вехи или её плановой даты | да |
| Фактическая дата есть, а закрытия в 1С нет (или наоборот) | нет, предупреждение |
| БС: нет % перевыставления за квартал | да для КУПК и РУПК БС |
| МП: нет KPI за квартал | да для МП |
| Суммарная загрузка сотрудника изменилась больше чем на 25 п.п. за квартал | нет, предупреждение |
| Сумма по сотруднику отличается от прошлого расчёта того же квартала больше чем на 10% | нет, предупреждение |
| Опережение этапа больше 100 дней | да, до решения |
| Сотрудник уволен в кадрах, а назначение не закрыто | да |
| Загрузка РП вне допустимого диапазона для его ранга, или набор проектов не утверждён | нет, предупреждение |

Пороги 25 п.п. и 10% — предложение, их утверждает Группа СОВ.

## 9. Интерфейсы

Нужны три входа: панель Группы СОВ, личный кабинет сотрудника и Excel-выгрузки. Руководители работают с выгрузками или с панелью в режиме чтения по своим проектам.

### 9.1 Панель Группы СОВ

1. **Обзор квартала.** Сколько проектов, этапов и сотрудников в расчёте; какие источники загружены и когда; сколько проблем и сумм в каждом статусе.
2. **Сотрудники.** Список с фильтрами: блок, проект, категория, работает или уволен, статус суммы. Карточка: назначения, вехи, коэффициенты, история начислений и правок.
3. **Проекты.** Очереди, этапы, вехи по плану и факту, NPV по кварталам, состав команды.
4. **Загрузка.** Выбор файла, предпросмотр изменений, «Применить», откат (раздел 5).
5. **Проблемы.** Результат автоконтролей с переходом к строке, которую нужно исправить.
6. **Ручные решения.** Перераспределение ±30%, корректировка стартового NPV, решения по опережению и расходной части, признак увольнения за нарушение. Каждое решение — с основанием и файлом или ссылкой.
7. **Расчёт и закрытие квартала.** Кнопки «Рассчитать» и «Закрыть квартал». Закрытие фиксирует снимок данных и редакции правил; после него начисления квартала менять нельзя, только корректировка в следующем.
8. **Журнал.** Кто, когда и что загрузил или исправил, с фильтром по сотруднику и проекту.

### 9.2 Личный кабинет сотрудника

- По каждому назначению: проект, этап, категория, дата начала, ПБ, доля на авансы и на финал.
- Таблица вех как в калькуляторе: план, индивидуальный срок, факт, дни опережения или просрочки, вес, коэффициенты, сумма, статус, дата выплаты.
- Комментарий к сумме: при каких NPV и К фин посчитана, или почему не выплачивается («Веха не участвует в расчёте», «Бонус по текущей вехе будет выплачен после выполнения предшествующих вех»).
- Для КУПК — график финальных выплат 50/25/25 с условием по NPV и текущим статусом каждой части; проценты на отложенную часть.
- Итог по статусам: выплачено, начислено, прогноз до конца этапа при закрытии оставшихся вех в срок и текущем NPV.

### 9.3 Выгрузки в Excel

- Выписка по проекту и этапу в виде листа «калькулятор», только значения, без формул и макросов.
- Сводная к выплате за квартал по всем блокам, с сравнением с прошлым кварталом.
- Файл к начислению в формате, который сейчас принимает расчёт зарплаты.
- Список проблем и список сотрудников со статусом «ручной расчёт».

### 9.4 Режим «что если»

Сотрудник в личном кабинете и Группа СОВ в карточке сотрудника подставляют свои значения и сразу видят сумму к выплате. Считает тот же движок по тем же правилам разделов 6–7, отдельных формул для моделирования нет.

| Что можно подставить | Кто | Как вводится |
| --- | --- | --- |
| Фактическая дата закрытия незакрытой вехи и ключевой вехи | все | дата или ползунок «дней до или после плана» от −100 до +100 |
| NPV текущий и NPV на контрольные даты частей 25% | КУПК, Группа СОВ | сумма или ползунок от −50% до +50% к текущему |
| % выполнения KPI по кварталам | МП, «вр. KPI (Вехи)», Группа СОВ | ползунок от 0 до 150% |
| % переданных к перевыставлению затрат | сотрудники БС, Группа СОВ | ползунок от 0 до 100% |
| Дата ухода, БГБ, % загрузки | только Группа СОВ | поле ввода |

- Пересчёт при каждом изменении, не дольше 1 секунды, без кнопки «Рассчитать».
- На экране две колонки — «сейчас» и «по сценарию» — и разница: по каждой вехе, по финальному бонусу и частям 50/25/25, по процентам, итого за этап и в ближайшую выплату.
- У каждой незакрытой вехи подсказка «цена дня»: на сколько рублей меняется бонус при сдвиге на один день, с учётом потолка 150% и нуля при просрочке 100 дней.
- Сценарий не сохраняется в реестр и не влияет на расчёт. На экране всегда видна пометка «Моделирование, не является обещанием выплаты». Кнопка «Сбросить» возвращает фактические значения.

### 9.5 Файл к начислению

Одна строка на одно начисление, файлы xlsx и csv (UTF-8, разделитель «;»). Формат рабочий, его можно поменять под требования расчёта зарплаты без переделки движка.

| Подразделение | БС ОУС |
| Проект, очередь | Тестовый проект, очередь 1 |
| Этап | 4 |
| Вид начисления | аванс за веху / финальный бонус / финал 50% / финал 25% / остаток при уходе / проценты на отложенную часть |
| Веха | Мотивационная веха 3 |

## 10. Доступ и персональные данные

Реестр содержит БГБ и суммы бонусов, поэтому доступ строится от минимума.

- Полный доступ к суммам и БГБ — только у Группы СОВ.
- Руководитель видит суммы только по своим проектам и своему ФП; БГБ сотрудников ему не показывается.
- Сотрудник видит только себя. Вход через корпоративную учётную запись, без отдельных паролей.
- Разработчики и тестировщики работают только на условных данных (раздел 11). Реальные данные попадают в систему только после приёмки на шаблоне и по решению Группы СОВ.
- Каждый просмотр карточки сотрудника другим пользователем и каждая выгрузка пишется в журнал.
- Хранение и обработка — в контуре компании; требования по информационной безопасности согласует HRIT.

## 11. Тестирование на шаблоне калькулятора

Приёмка проходит только на шаблоне калькулятора с условными данными. Реальные калькуляторы, ФИО, БГБ и NPV проектов в тестировании не используются и разработчику не передаются.

**Как проверяем**

1. Группа СОВ готовит набор кейсов из таблицы ниже: условные сотрудники («Тестов 1»…), «Тестовый проект», придуманные даты и суммы.
2. Каждый кейс заполняется в копию шаблона и пересчитывается в Excel. Это эталон.
3. Те же данные загружаются в систему через загрузчики; вехи — в формате «Листа для загрузки вех».
4. Сравниваются все результаты: ПБ, веса, аванс по каждой вехе, финальный бонус, части 50/25/25, остаток при уходе, проценты, даты выплат и комментарии. Допуск — 1 ₽ на сумму.
5. Где шаблон расходится с СОВ (таблица расхождений ниже), эталон правится по решению Группы СОВ до сравнения.
6. Приёмка — все кейсы совпали. После этого Группа СОВ сама решает, когда и на каких реальных данных запускать параллельный расчёт.

## 12. Этапы разработки

Каждый этап заканчивается проверкой, и следующий не начинается, пока она не пройдена. Реальные данные появляются только на шаге 5.

1. **Согласование правил.** Решения по расхождениям шаблона (раздел 11) и открытым вопросам (раздел 13), эталонные файлы T01–T18. Проверка: Группа СОВ утверждает правила и эталоны.
2. **Реестр и движок.** Таблицы раздела 4, расчёт по разделу 6, увольнение и перевод, загрузка из шаблона и файлов. Проверка: все кейсы совпадают с эталоном до 1 ₽.
3. **Панель Группы СОВ.** Загрузка с предпросмотром, автоконтроли, ручные решения, выгрузки, журнал, закрытие квартала. Проверка: Группа СОВ проводит целый условный квартал на тестовых данных.
4. **Интеграции.** Автозагрузка из 1С IHR, УП ШР, «Мотивационных вех» и отчёта по NPV. Проверка: образцы выгрузок с условными данными загружаются без ручных правок.
5. **Параллельный расчёт.** По решению Группы СОВ: один блок, 1–2 квартала рядом с калькуляторами, затем остальные блоки. Проверка: каждое расхождение объяснено.
6. **Личный кабинет.** Включает режим «что если» (в панели Группы СОВ он есть уже с шага 3). Открывается сотрудникам только после шага 5, сначала для одного блока.
7. **Второй этап.** Вид СОВ «KPI (Вехи от NPV)», проекты-исключения БС и отложенные бонусы по старой СОВ.
