# Интерфейс прототипа

Прототип — локальное веб-приложение на Streamlit (`uv run streamlit run app/main.py`), открывается в браузере на Windows и macOS. Разработка и проверки сейчас выполняются на Mac; запуск на Windows проверяется отдельно перед эксплуатацией. Вход — демонстрационный выбор роли и условного пользователя (корпоративной авторизации в прототипе нет). Все экраны читают реестр; писать предметные данные могут только загрузка, ручные решения и закрытие квартала. Изменения, просмотры карточек и выгрузки попадают в журнал.

## 1. Роли в прототипе

| Роль | Видит | Может |
| --- | --- | --- |
| Группа СОВ | всё | загружать, решать, считать, закрывать квартал, «что если» по любому сотруднику |
| Руководитель (РФП, РП) | свои проекты и ФП, без БГБ | смотреть, выгружать выписки |
| Сотрудник | только себя | смотреть, «что если» по своим назначениям |

Права проверяются в сервисном слое, а не только скрытием кнопок.

## 2. Панель Группы СОВ (ТЗ 9.1)

1. **Обзор квартала** — выбор квартала; число проектов, этапов, сотрудников в расчёте; какие источники загружены и когда; число проблем; суммы по `calc_status`.
2. **Сотрудники** — таблица с фильтрами (блок, проект, категория, работает / ушёл, статус). Карточка: назначения, вехи как в калькуляторе, коэффициенты, история начислений и правок, кнопка «Что если».
3. **Проекты** — очереди, этапы, вехи план/факт, NPV по кварталам, команда.
4. **Загрузка** — выбор файла (`samples/*` для теста), распознанный тип, предпросмотр «добавится / изменится / не распознано» со строками, «Применить», список загрузок с «Откатить».
5. **Проблемы** — результат автоконтролей (`CALC_RULES` §12.2), фильтр блокирующие / предупреждения, переход в карточку.
6. **Ручные решения** — перераспределение ±30%, корректировка стартового NPV, решение по опережению > 100 дней, расходная часть 5 этапа, выплата вне сессии. Каждое — с основанием и ссылкой на файл.
7. **Расчёт и закрытие квартала** — «Рассчитать» (все или выбранные), «Закрыть квартал» (снимок данных и редакции правил; после закрытия начисления квартала не меняются), выгрузки: файл к начислению, выписки, сводная.
8. **Журнал** — кто, когда, что, было / стало, основание; фильтр по сотруднику и проекту.

## 3. Личный кабинет (ТЗ 9.2)

- Назначения: проект, этап, категория, дата начала, ПБ, пулы авансов и финала.
- Таблица вех: план, индивидуальный срок, факт, отклонение, вес, сумма, статус, дата выплаты; комментарий к сумме (NPV и К фин, или почему не выплачивается).
- КУПК: график 50/25/25 с условием по NPV и статусом каждой части; проценты.
- Итог: выплачено, начислено, прогноз до конца этапа при закрытии оставшихся вех в срок и текущем NPV.
- Постоянная пометка «Расчёт предварительный» на суммах со статусом «прогноз».

## 4. Режим «что если» (ТЗ 9.4)

Открывается из карточки сотрудника (Группа СОВ) и из кабинета (сотрудник). Считает тот же движок, что и основной расчёт: сценарий — это копия входа назначения с подменёнными значениями, переданная в ту же функцию.

| Что подставить | Кто | Элемент |
| --- | --- | --- |
| Факт незакрытой промежуточной и ключевой вехи | все | дата или ползунок «дней до/после плана» −100…+100 |
| NPV текущий и NPV на контрольные даты 25% | КУПК, Группа СОВ | сумма или ползунок −50…+50% к текущему |
| KPI по кварталам | МП, Группа СОВ | ползунок 0…150% |
| Доля перевыставления | сотрудники БС, Группа СОВ | ползунок 0…100% |
| Дата ухода, БГБ, загрузка | только Группа СОВ | поля |

- Пересчёт на каждое изменение, без кнопки, не дольше 1 секунды.
- Две колонки «сейчас» и «по сценарию» и разница: по каждой вехе, финалу и частям, процентам, итого за этап и в ближайшую выплату.
- У каждой незакрытой вехи — «цена дня»: на сколько рублей меняется сумма при сдвиге факта на один день (с учётом потолка 150% и нуля при просрочке 100 дней).
- Сценарий не сохраняется в реестр. Всегда видна плашка «Моделирование, не является обещанием выплаты». «Сбросить» возвращает фактические значения.
- Ползунки и поля — в `st.session_state`; пересчёт — чистая функция движка, при необходимости с `st.cache_data` по входу.

На M4 режим доступен Группе СОВ. Для проверки на уже закрытых условных кейсах
есть явный переключатель «Исторический сценарий»: он разрешает подменять
закрытые факты и финансовые условия прошлого. В обычном сценарии текущий NPV
и доля БС подставляются только в незакрытые события; закрытые значения сохраняются.
В сценарии факт одновременно означает закрытие в 1С. Контрольные NPV q1/q2
можно подставить отдельно. БГБ и загрузка меняются по каждому исходному периоду.
Квартальные NPV и доли БС при переносе дат автоматически не перечитываются:
остальные финансовые условия копии фиксированы. KPI МП пересобирается из
квартальной истории по новому порядку вех общей функцией адаптера.

Ближайшая выплата считается от явно выбранной даты (по умолчанию — последний
день выбранного квартала). Итог включает только рассчитанные суммы; неполные,
ожидающие и приостановленные суммы видны в сравнении со своими статусами.
Смена сотрудника, назначения или ревизии данных сбрасывает сценарий.
Просмотр карточки записывается при её открытии; изменение сценарных полей,
раскрытие режима и сброс не создают новых событий журнала.

## 5. Выгрузки (ТЗ 9.3)

- Выписка по проекту и этапу — xlsx в виде листа «калькулятор», только значения.
- Сводная к выплате за квартал с сравнением с прошлым кварталом.
- Файл к начислению — `docs/DATA_FORMATS.md`, раздел 5.
- Список проблем и сотрудников со статусом «ручной расчёт».
