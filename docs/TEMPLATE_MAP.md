# Шаблон калькулятора: карта ячеек, правки и отличия от ТЗ

Файл: `reference/template/bonus_template_empty.xlsx` — обезличенная копия шаблона «bonus_БС с К перевыставления 90+10» без макросов, данных и кэша значений. Формулы не тронуты. Шаблон — эталон **текущей практики**; эталон **по ТЗ** получается правками P1–P7 и правилами O1–O3, S1–S3 (ниже).

Заполненные и пересчитанные копии для каждого кейса — `reference/examples/<ID>_template.xlsx` и `<ID>_spec.xlsx`. Их можно открыть в Excel или LibreOffice и пройти расчёт по ячейкам.

## 1. Лист «калькулятор»

### Шапка проекта

| Ячейка | Что | Заполняет стенд из кейса |
| --- | --- | --- |
| B1 | название проекта | `project` |
| F1 | переход из предыдущего этапа (Да/Нет) | `continues_from_prev_stage` |
| F2 | старт нового этапа | `new_stage_start` |
| F3 | отношение к БС (Да/Нет) | `bs.enabled` |
| G3 | доля переданных к перевыставлению затрат | `bs.share_transferred` |

### Блок сотрудника

Два блока: первый — колонки K–O, второй — P–T. Ниже буквы первого блока; у второго сдвиг на 5 (K→P, M→R, N→S, O→T).

| Строка | Ячейка | Что |
| --- | --- | --- |
| 1 | O1 | категория: КУПК (РП/ЗРП), КУПК, РУПК, МП |
| 2 | O2 | должность |
| 3 | O3 | ФИО (по нему лист процентов ищет сотрудника) |
| 4 | O4 | NPV стартовый |
| 5 | O5 | дата начала работы на этапе |
| 6 | O6 | длительность `=MAX($G15:$G39,K15:K39)-O$5+1` |
| 7 | O7 | ПБ `=SUM(O45:O79)` |
| 8 | O8 | пул авансов `=O7*0.67` (в калькуляторах 5 этапа вручную 0,33; стенд ставит `=O7*0.33`) |
| 9 | O9 | пул финала `=O7-O8` |
| 10 | O10 | К фин (пределы, правило низкого NPV) |
| 11 | O11 | NPV текущий |
| 12 | K12, O12 | подпись «Дата ухода с проекта (этапа)» и дата ухода |
| 13 | O13 | остаток при уходе (формула массива) |
| 16–35 | | промежуточные вехи (по строке на веху) |
| 36 | | ключевая веха |
| 37–39 | | выплаты финальной части |
| 45–79 | K–O | периоды: K с, L по, M загрузка, N БГБ, O = N/365×(L−K+1)×M |

### Строки вех (16–35) и ключевой вехи (36)

| Колонка | Что |
| --- | --- |
| C | номер этапа |
| E | наименование вехи (по нему лист процентов ищет веху) |
| F | корпус |
| G | плановая дата |
| H | фактическая дата |
| I | `=G−H` отклонение от плана проекта |
| J | дата выплаты `=DATE(YEAR(H),ROUNDUP(MONTH(H)/3,0)*3+2,10)` |
| K | индивидуальный срок сотрудника |
| M | вес (или текст «Веха не участвует…») |
| N | сумма аванса (в строке 36 — финал или остаток) |
| O | комментарий; у МП — KPI за квартал вехи (вводится) |

Строки 37–39: H37 = H36, H38 = H36 + 90, H39 = H38 + 90; J — дата выплаты; O37–O39 — NPV на эти даты (вводится); N37 = 50% финала + проценты (у РУПК и МП — 100%), N38, N39 — по 25% + проценты или текст «Выплаты приостановлены», «Принять решение о перерасчете…».

## 2. Лист «проценты на отложенную часть»

- Сводка B6:H37 по сотрудникам: D — проценты РУПК и МП, E, F, G — проценты трёх частей КУПК, H — итого.
- Блок сотрудника с шагом 34 строки: 39, 73, 107… (B39 — ФИО, C39 — категория).
- В блоке строки 46–65 — вехи: B веха, C аванс, D дата выплаты аванса, E отложено `=C/67*33`, I ставка ЦБ (вводит Группа СОВ), J/K, M/N, P/Q — дни и проценты до дат K44, N44, Q44 (даты выплаты частей). У КУПК множители 0,5 / 0,25 / 0,25.

## 3. Другие листы

- «+- 30%» — перераспределение для РУПК (заполняется вручную; в стенде не используется).
- «тех.лист» — списки категорий и должностей.
- «Лист для загрузки вех» — формат выгрузки вех из 1С (см. `docs/DATA_FORMATS.md`, раздел 3).

Код — `tools/template_harness/contract.py`. Формулами шаблона их не выразить, поэтому они применены к результату; каждая формула там сверяется с тем, что посчитал шаблон.

| Код | Правило | Кейсы |

| S1 | «ждёт предыдущую веху» | T12 |

## 6. Особенности шаблона, которые не правились (тестами не покрыты)

- Обнуление при просрочке ≥ 100 дней считается от плановой даты проекта (`$I16<-100`), а К срока — от индивидуального срока. При инд. сроке с просрочкой больше 100 дней формула даёт отрицательный аванс. Приложение: всё от `plan_eff`, не меньше 0 (CALC_RULES И-7).
- МП с KPI ниже 50%: отрицательный множитель (CALC_RULES И-3).
- Ставка ЦБ вводится вручную по каждой вехе; в приложении — из истории ставок.
- Праздники не учитываются, только суббота и воскресенье.
- Сотрудник на листе процентов ищется по ФИО, веха — по наименованию: два сотрудника с одинаковым ФИО или две вехи с одним названием в одном калькуляторе ломают расчёт. В приложении — только ключи (табельный номер, код вехи).
- Часть 25% (1), выплаченная с задержкой, индексируется до исходной даты (CALC_RULES И-4).
